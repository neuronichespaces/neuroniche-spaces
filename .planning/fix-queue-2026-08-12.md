# Fix queue — from the 2026-08-12 full-stack + security audit

Source report: `docs/audit-2026-08-12-fullstack-security.md`.
Work top-down. Sizes: **S** = under 30 min, **M** = an hour or two, **L** = a session.

---

## Do first — things that are broken or cost money

- [ ] **[Critical · M] Lock down the AI business-case endpoint** — `src/app/api/business-case/draft/route.ts`
  Right now anyone on the internet can hit the "write my business case with AI" button
  on your behalf, without signing in, as often as they like. Each press makes about
  five paid AI calls. Someone could run up your AI bill overnight and make the feature
  unusable for real customers. Needs: require sign-in, add a simple per-user/per-IP
  limit, and cap how many sections one request can draft.

- [ ] **[High · S] Let the browser talk to the database** — `next.config.ts:20`
  The security-headers rule currently says "this page may only contact its own server".
  Supabase lives on a different address, so once the app is deployed for real, sign-in,
  saving an audit, saving a room plan and saving a business case will all silently do
  nothing. Add the Supabase address to the `connect-src` line, then do one signed-in
  smoke test to confirm.

- [ ] **[High · S] Validate what gets posted to the AI endpoint** — `src/app/api/business-case/draft/route.ts:26`
  The server currently trusts whatever it's sent. `zod` is already installed and unused
  here — one small schema check rejects junk and caps how much can be sent, which is
  half of the abuse fix above.

- [ ] **[High · M] Stop hostile text steering the AI** — `src/lib/businesscase/aiDrafter.ts:52-66`
  The organisation name is pasted straight into the AI's instructions. A crafted name
  can override your rules — including the "no clinical language, no invented dollar
  figures" rules, which live *only* in that instruction text. Clean and length-limit the
  name before it goes in, and keep the human review step mandatory.

- [ ] **[High · S] Patch two known dependency vulnerabilities** — run `npm audit fix`
  Two supporting libraries (`js-yaml`, `nanoid`) have published high-severity issues.
  Neither is in the customer request path, so the practical risk is low, but your CI
  security check flags them. The standard fix command resolves both.

## Do before anyone can pay you

- [ ] **[Medium · M] Make a payment actually do something** — `src/app/api/stripe/webhook/route.ts:36-49`
  When Stripe tells the app "this customer paid", the app writes a log line and nothing
  else. There is no record that anyone is a paying customer. Wire it to mark the
  organisation as paid, using Stripe's event id so a repeated message can't double-count.

- [ ] **[High · S] Add the pricing page to the menu** — `src/components/NavBar.tsx:11-18`
  `/billing` exists and works but nothing links to it, so no customer can find it. One
  line. **Do this one *after* the webhook item above** — otherwise people can pay and
  get nothing.

## Reliability — silent failures users can't see

- [ ] **[Medium · M] Show errors when saving or loading fails** — `src/app/business-case/page.tsx:92-118`, `src/app/audit/page.tsx:131`, `src/app/costing/page.tsx:181,203`
  Five places load or save data without handling a failure. Worst case: the business
  case page fails to load an existing saved case, looks like "nothing saved yet", and
  the user overwrites their previous work. Others leave a "saving…" spinner turning
  forever with no message. Add a visible error message to each.

## Hardening — worth doing, not urgent

- [ ] **[Medium · L] Remove `unsafe-inline` from the script security policy** — `next.config.ts:12`
  This weakens the main defence against injected scripts. The proper fix needs the same
  middleware layer the rate limiting needs, so schedule them together.

- [ ] **[Medium · S] Reject cross-site requests to the checkout endpoint** — `src/app/api/checkout/route.ts:9`
  Harmless today, but the moment checkout is tied to a signed-in account this becomes a
  real hole. An origin check plus the shared rate limiter covers it.

- [ ] **[Medium · S] Refuse to send the AI key to an unexpected address** — `src/lib/businesscase/aiDrafter.ts:31,62`
  The AI server address comes from a settings file, and the key is sent to whatever
  that says. A typo or a tampered setting would hand your key to a stranger. Check the
  address against a short allowlist at startup.

- [ ] **[Medium · S] Fail loudly when the admin database key is missing** — `src/lib/supabase/server.ts:31-35`
  Today it quietly falls back to the limited key, so a misconfigured deploy fails later
  in confusing ways instead of immediately at startup.

- [ ] **[Medium · M] Move the sign-in session into secure cookies** — `src/lib/supabase/client.ts:26`
  The session currently sits in browser storage where any script on the page can read
  it. Switch to `@supabase/ssr` cookies (`httpOnly`, `secure`, `sameSite`) when
  server-side auth is added.
